Tests of the boundary go here: the real one, a systemd user scope around bubblewrap, that contains the executor, stops everything it started and is seen empty.

- `test_end_to_end.py`: the one end-to-end test. One request through every piece that is real so far (an input check with a reference, a gate, the opening fingerprint of a real place, the boundary, the statement the script leaves, the closing freeze, the kept statement), from the input document to the outcome record; it also covers the instruction and notice on standard input, and the run area made and removed. Later tickets extend it; they do not add their own.
- `test_statement.py`: the statement a script leaves in its run area is kept byte for byte, copied to the document's location and read as none, right shape or wrong shape; a script cannot change a reference.
- `test_arguments.py`: arguments (the executor's and a gate's), a records location with `$`, `%` and a backslash, and a place whose own path holds every awkward name of the table, arrive and are protected unchanged.
- `test_boundary.py`: what is left after a child outlives its script and after the command is killed hard, what a script cannot write, a boundary whose tools fail (the run could not start), and a script that kills itself.
- `test_tool_output.py`: a stand-in tool, written and run by the harness's `run_a_stand_in_tool`, prints a large event stream, with one line longer than any line is read; the run ends with its record, the counts are read, and the peak size of the processes stays far below what reading the stream whole would take; and the helper refuses, before starting anything, a program that would resolve outside the test's own folder.
- `test_reach.py`: the reach through the real box: what is hidden (the home folder, a folder beside the place, the records, the user's runtime folder and its sockets, the real `/tmp`), what is read-only and never written (the system, each reference, each visible folder: by a plain write, through `/proc/self/root` or by a remount), and what is writable and gone with the run (the place stays; `/tmp` and home go). Run with the test's folders under the temporary folder and under another, and with the run area in either.
- `test_git_in_the_box.py`: git reads in the box (status, diff, log) in a linked working copy, the usual place, and in a plain checkout, and cannot write: add, commit, a change to the configuration and a new file in the hooks folder all fail, for both git folders of a linked working copy; the working files stay writable and the closing freeze records them; the working files of the repository the place was made from stay hidden.
- `test_changes_to_place.py`: `changes_to_place: not` with the command driver: no file in the place can be created, changed or deleted, while `/tmp`, the run area and the statement path stay writable and the statement reaches its copy target; with `allowed` or no setting the place is changed as before.
- `test_login_copy.py`: a stand-in tool (its login a file, or a link to one) replaces its login the way the real tool does (a temporary file and a rename, with a lock file); it works because the login arrived as a copy, and the original is unchanged after the run.
- `test_scope_names.py`: a run's scope names are its own: two runs of one request id at once, held units of old names left alone, a check during a run's gates.

They skip, with the reason, on a machine without the boundary (`tests/rehearsal/the_boundary.py`), and fail instead where `SHUTTLE_REQUIRE_BOUNDARY` is set, which the hosted runner sets. No test here sleeps or reads a clock: a script says it is up through a pipe, and the time limit is the boundary's.
